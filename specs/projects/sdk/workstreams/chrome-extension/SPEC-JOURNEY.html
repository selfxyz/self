How to review this page

Every screen a user can land on, across the three journeys, one row per screen: what is on it, every state it can be in, and which Euclid components build it. Screens marked exists shipped in the spike and need polish; screens marked new are designed here for the first time. The five design questions at the bottom are where we explicitly need design/UX judgment, everything else is review-and-veto.

Surfaces: Phone Self app screens · Extension popup window (430x800) · Web the Enterprise hosted verification page.

The one locked interaction: during setup, the user visually compares 4 emojis on both devices, then presses one explicit button on the phone ("Encrypt & send my account"). The check is a gate on the path, not decoration beside it.

DQ-1 design input open

Is the 64-emoji SAS set right, seen for one second at arm's length?

The security check lives or dies on fast visual comparison across two screens. The current set (animals, food, objects; see mobile-sdk-alpha/utils/sas.ts) was engineering-picked. Design should vet: distinguishability at 32-36px, cross-platform rendering differences (Apple vs Noto emoji), and colorblind-safe pairs. The order is protocol-locked once shipped: entries can only be appended, never reordered.

DQ-2 design input open

What is the biometric affordance on custody and unlock buttons?

Euclid has no Touch ID / passkey icon (the old FaceIdIcon was removed in 1.4.6). Apple's guidelines restrict use of their Touch ID mark. Options: a generic fingerprint glyph, a key/shield metaphor from the existing icon set (LockIcon, ShieldLockIcon), or text-only buttons. Needed for A5, B2, C4.

DQ-3 design input open

How does an expired or superseded QR look and recover?

A1's QR can expire (5 min), be superseded (user re-opens the popup), or fail (relayer down). Proposal: expired = blur + centered regenerate button; error = inline retry row under the frame. Needs a design pass with the new QRDisplay component states.

DQ-4 design input open

Success motion: which Lottie, and where does it come from?

Euclid's StatusState takes a caller-supplied Lottie and the library ships none. A6, B5, and the phone's link success all want the same checkmark motion. One asset, sourced once, reused everywhere; needs design to produce or pick it.

DQ-5 design input open

What does the popup frame keep and drop from the phone home?

The mini home reuses the phone's home screen inside a 430x800 popup. Points balance, earn/referral modules, and notifications likely read as noise in a browser popup; the ID card and settings clearly stay. Design call on the exact cut list, plus whether the popup gets a distinct header treatment so it reads as "Self in your browser" rather than a shrunken phone app.
