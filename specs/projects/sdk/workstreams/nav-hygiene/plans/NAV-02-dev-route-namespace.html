Why

Dev-only routes are scattered. /debug/keychain is correctly gated on import.meta.env.DEV at registration. /tunnel/kyc-pending is also DEV-gated but lives under the tunnel namespace. The three /proving/dialogue* routes are reachable only via DevRouteMenu but have no DEV gate. NAV-02 standardizes: every dev-only route moves under /dev/* and is gated on import.meta.env.DEV at the registration site.

Depends on NAV-01 (classification). Consumes the dev and component rows from the disposition table.

Decisions

Locked in on 2026-05-25. The widget at Open Questions remains the editing surface; this block plus DECISIONS.md are the durable record.

  • nav-02-q1-dialogue-move · Custom decision

    Should the three /proving/dialogue* routes move to /dev/* or stay at /proving/* as component-showcase routes?

    Decision: neither — discard the three dialogue screens. Clunky, unused by any production flow (the only entry point is DevRouteMenu), not worth namespace surgery. Delete the routes + screen files + DevRouteMenu entries in this PR. Re-introducing a polished version is tracked in the SDK future backlog.

    "I looked into the dialog, but it seems very clunky. I think that for now we can discard that screen unless it is used in the app. and put in the backlogs that we'll have to improve it." Confirmed: no production navigate() calls target these paths — only App.tsx registrations and DevRouteMenu.

  • nav-02-q2-tunnel-kyc-pending · Decided

    Move /tunnel/kyc-pending to /dev/* or keep at /tunnel/* (subject to NAV-08 rename)?

    Decision: keep at /tunnel/kyc-pending until NAV-08. NAV-08's namespace rewrite will sweep it to /disclose/kyc-pending; it never enters /dev/* at all.

    "I don't really understand your question, the /dev/ seems to not be used anywhere else in the docs. so why should we have this stuff only for that screen which is actually not only for devs. there has to be a misunderstanding somewhere." Reconciliation: NAV-02 creates the /dev/* namespace — it does not exist anywhere else today. The framing of the original question implied /dev/* was already an established home for dev fixtures; it isn't. With the decision above, kyc-pending sidesteps the question entirely.

Scope

  • Move /debug/keychain → /dev/keychain. Keep the existing {import.meta.env.DEV && <Route ... />} wrapping pattern.
  • Delete the three /proving/dialogue* routes — and the screen files SimpleDialogueScreen.tsx, DialogueWithCtaScreen.tsx, ProofGenerationDialogueScreen.tsx. Remove their three entries from DevRouteMenu.tsx. Confirm with grep that no navigate() call targets these paths.
  • Leave /tunnel/kyc-pending alone in this PR — NAV-08 sweeps it to /disclose/kyc-pending.
  • Update DevRouteMenu.tsx to add a "Dev" group at the top of the menu containing every /dev/* entry (currently just /dev/keychain after this PR).
  • Document the gating pattern in packages/webview-app/AGENTS.md — one paragraph: "dev-only routes register under /dev/* with {import.meta.env.DEV && ...}. NAV-02 is the workstream that established this namespace."

Out of Scope

  • No changes to isDemoMode() or any ?mock=... URL-param logic. That mechanism is orthogonal (runtime data injection, not registration gating).
  • No changes to component-level DEV gates (HomeScreen restart button, MockRegistrationFailureButton, etc.). Those stay as-is.
  • No process.env or __DEV__ rewrites. Webview-app already standardizes on import.meta.env.DEV.
  • NAV-12 (rename tunnel → embed) is separate; this plan touches /tunnel/kyc-pending only if Q2 says "move to /dev/*."

Required Files

  • packages/webview-app/src/App.tsx (route registrations at lines ~130, 156, ~143–145)
  • packages/webview-app/src/components/DevRouteMenu.tsx (entry list)

Approach

Step 1 — Move /debug/keychain

In App.tsx line 130, change:

{import.meta.env.DEV && <Route path="/debug/keychain" element={<KeychainDebugScreen />} />}

to:

{import.meta.env.DEV && <Route path="/dev/keychain" element={<KeychainDebugScreen />} />}

In DevRouteMenu.tsx, update the matching entry's href.

Step 2 — Delete the dialogue routes

In App.tsx (lines 151–153), remove the three dialogue route registrations. Delete the screen files (SimpleDialogueScreen.tsx, DialogueWithCtaScreen.tsx, ProofGenerationDialogueScreen.tsx) and their imports. Remove the three entries from DevRouteMenu.tsx (lines 75–77).

The follow-up to re-introduce a polished dialogue showcase is tracked in FUTURE-BACKLOG.html (item fb-006).

Step 3 — /tunnel/kyc-pending is not in scope

The screen stays on its current path until NAV-08 renames the entire /tunnel/* namespace. No code change in this PR.

Step 4 — DevRouteMenu reorganization

Add a "Dev" group as the first group in DevRouteMenu.tsx's GROUPS array containing every /dev/* route. Audit existing groups and remove duplicates.

Step 5 — Document the rule

Add to packages/webview-app/AGENTS.md under a "Routes" or "Conventions" heading:

Dev-only routes register under /dev/* and are gated on import.meta.env.DEV at the registration site. Production builds never include them. DevRouteMenu is the only allowed entry point.

Validation

  • cd packages/webview-app && yarn build — clean build.
  • Run dev server (yarn dev). Verify:
    • DevRouteMenu shows a "Dev" group with every /dev/* route.
    • Clicking each /dev/* entry lands on the right screen.
    • Navigating directly to the old paths (/debug/keychain) returns the catch-all redirect to /.
  • Run a production-style build (yarn build then serve dist/). Verify /dev/* routes return the catch-all redirect (DEV gate stripped them).
  • grep -r "/debug/keychain" packages/webview-app/src returns no hits.
  • grep -r "/proving/dialogue" packages/webview-app/src returns no hits.
  • grep -rn "SimpleDialogueScreen\|DialogueWithCtaScreen\|ProofGenerationDialogueScreen" packages/webview-app/src returns no hits.
