Why

Per SPEC invariant #1: every route declares which mode(s) it belongs to. Today, mode coupling is implicit — ModeBoot redirects between mode roots, per-screen guards check useOperatingMode(), and the router itself can't reject an embed flow that tries to reach /settings. NAV-13 introduces a ModeRoute wrapper that hides routes not matching the current mode. Removes the scattered guards. Pairs with NAV-08 — routes get tagged the moment their paths change.

Decisions

Locked in on 2026-05-25. See DECISIONS.md.

  • nav-13-q1-wrapper-shape · Decided

    Wrapper API: <ModeRoute mode='…' path='…' element={…} /> or <Route element={<ModeGuard mode='…'>…</ModeGuard>} />?

    <ModeRoute>. Single declaration; ~40 call sites stay as one-liners. Wrapper logic is non-trivial (must render a <Route> to satisfy react-router) — pay that cost once.

  • nav-13-q2-mismatch-behavior · Decided

    On mode-mismatch (e.g. embed user hits /settings): 404, redirect home, or fail-closed?

    Mode-aware behavior. Self-app users → <Navigate to="/" replace />. Embed users → lifecycle.setResult({ success: false, errorCode: 'route_not_allowed' }) + lifecycle.dismiss(). Host gets a clean failure signal; self-app user lands somewhere sensible.

Scope

  • Implement the ModeRoute wrapper per Q1. Two shapes: 
    // Option A: <ModeRoute> (recommended)
<ModeRoute mode="self-app" path="/settings" element={<SettingsScreen />} />
<ModeRoute mode="embed" path="/disclose/request" element={<DiscloseScreen />} />
<ModeRoute mode="shared" path="/disclose/kyc-pending" element={<KycPendingScreen />} />
<ModeRoute mode="dev" path="/dev/keychain" element={<KeychainDebugScreen />} />

// Option B: <ModeGuard> inside <Route>
<Route path="/settings" element={<ModeGuard mode="self-app"><SettingsScreen /></ModeGuard>} />
  • Replace every <Route> in App.tsx with the wrapper. Each gets a mode declaration from the NAV-01 disposition table.
  • Implement mode-mismatch behavior per Q2:
    • mode-aware (recommended): self-app → redirect to /; embed → setResult({success:false, error:'route_not_allowed'}) + dismiss; dev/shared → render normally.
    • always-home: redirect to / regardless. Wrong for embed.
    • 404: render a 404 component. Bad for embed UX.
  • Remove the implicit mode coupling in ModeBoot — specifically the path-prefix checks (path.startsWith('/tunnel')) become unnecessary because ModeRoute enforces it route-by-route.
  • Add unit tests for ModeRoute behavior: each (mode, route-mode) pair → correct outcome.

Out of Scope

  • Route path renames — owned by NAV-08 (shared PR).
  • Per-screen guards like HomeScreen's "no documents → onboarding" — that's a data-dependent redirect, not mode-based. Stays.
  • Mode literal rename — NAV-12.
  • DEV gating — /dev/* routes are still wrapped with {import.meta.env.DEV && ...}. mode="dev" in ModeRoute is additional metadata, not a replacement for the build-time gate.

Approach

Step 1 — Define the wrapper

Per Q1 → mode-route (recommended):

type RouteMode = 'self-app' | 'embed' | 'shared' | 'dev';

export function ModeRoute({ mode, path, element }: {
  mode: RouteMode;
  path: string;
  element: ReactNode;
}) {
  const { mode: currentMode } = useOperatingMode();
  const lifecycle = useSelfClient().lifecycle;

  // shared + dev always render
  if (mode === 'shared' || mode === 'dev') {
    return <Route path={path} element={element} />;
  }

  // self-app route + self-app mode → render
  // embed route + embed mode → render
  const routeIsForCurrentMode =
    (mode === 'self-app' && currentMode === 'self-app') ||
    (mode === 'embed' && currentMode === 'embed');

  if (routeIsForCurrentMode) return <Route path={path} element={element} />;

  // Mismatch — behavior per Q2
  return <Route path={path} element={<ModeMismatchHandler routeMode={mode} />} />;
}

function ModeMismatchHandler({ routeMode }: { routeMode: RouteMode }) {
  const { mode } = useOperatingMode();
  const lifecycle = useSelfClient().lifecycle;
  useEffect(() => {
    if (mode === 'embed') {
      lifecycle.setResult({ success: false, error: 'route_not_allowed' }).catch(() => {});
      lifecycle.dismiss();
    }
  }, [mode]);
  if (mode === 'self-app') return <Navigate to="/" replace />;
  return null;
}

Step 3 — Simplify ModeBoot

After NAV-13: ModeBoot's "if path starts with /tunnel and mode is wallet, redirect to /" check is redundant — ModeRoute handles it. Delete those lines (lines 76–78 in current ModeBoot).

The fail-closed guard (lines 39–62) stays — it's about the verificationRequest validity, not route access.

Step 4 — Unit tests

Cases:

  • mode='self-app' route, currentMode='self-app' → renders element
  • mode='self-app' route, currentMode='embed' → renders Navigate("/") (in self-app), or dismisses (in embed... wait, this case shouldn't happen — embed user shouldn't hit a self-app route. Test the handler dispatches per Q2.)
  • mode='shared' route, any mode → renders element
  • mode='dev' route, any mode → renders element (DEV-gated at registration is build-time concern)
