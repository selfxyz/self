Why

Screens pass forward/backward/return targets through location.state with inconsistent slot names. The same intent — "where to go after this" — is called nextPath in onboarding and returnTo in recovery. Recovery additionally encodes returnTo into the URL query string. 7 local TS interfaces describe overlapping shapes; no shared NavState type exists. NAV-09 standardizes slot names, introduces a shared type, and decides on URL vs state for return paths.

Decisions

Locked in on 2026-05-25. See DECISIONS.md.

  • nav-09-q1-canonical-names · Decided

    Single name for "forward target," or keep nextPath + returnTo with a semantic split?

    Single name: nextPath. Rename returnTo → nextPath in the ~4 recovery files. NavState exposes only nextPath.

  • nav-09-q2-url-returnto · Decided

    Recovery's ?returnTo= URL param: keep, deprecate, or migrate to state-only?

    Migrate to state-only. Drop the URL-param plumbing entirely. Page-reload survival is low-value in a webview.

Scope

  • Resolve Q1 (single canonical name for forward target) and Q2 (URL param vs state for returnTo).
  • Introduce a shared NavState type in packages/webview-app/src/types/navState.ts: 
    export interface NavState {
  /** Forward target after current screen completes. Successor of legacy `returnTo`/`nextPath`. */
  nextPath?: string;
  /** Back target if non-default. */
  backPath?: string;
  /** Document selection context, when forwarded through a flow. */
  countryCode?: string;
  documentType?: string;
  documentTypes?: string[];
  /** Tunnel/embed result payload — set only by tunnel screens. */
  result?: { success: boolean; error?: string; source?: string };
  /** Home-screen redirect suppression. */
  skipOnboardingRedirect?: boolean;
  /** EU-ID NFC inputs. */
  canValue?: string;
  useCan?: boolean;
  mrz?: { documentNumber: string; dateOfBirth: string; dateOfExpiry: string };
  /** Provider integration. */
  providerResult?: KycProviderResult;
}
  • Migrate the 7 local types to Partial<NavState> + intersection for screen-specific extensions where needed.
  • Rename every returnTo read/write to nextPath per decision q1. Affects ~4 recovery files plus the URL-param encoding (which goes away in the next bullet).
  • Remove the ?returnTo= URL-param plumbing per decision q2. Recovery screens read exclusively from state.nextPath.
  • Update packages/webview-app/AGENTS.md with a "Navigation state" section linking to NavState + describing the rules.

Out of Scope

  • No new tests. Type-only changes; existing flow tests catch regressions.
  • No bridge schema changes. VerificationResult stays unchanged.
  • No URL-shape changes beyond removing ?returnTo= (if Q2 → state-only).
  • No state.backState generalization. It's a one-off in tunnel-proof-receipt; document it as such.

Approach

Step 1 — Author NavState

Single source of truth. Every location.state read/write across webview-app uses this type.

Step 2 — Mechanical renames (decision q1)

// Before (recovery screens)
const returnTo = searchParams.get('returnTo') ?? state?.returnTo;

// After
const nextPath = state?.nextPath; // URL param drops with q2 (next step)

Step 3 — Drop the URL param (decision q2)

// Before (LaunchRecoveryScreen, SecretPhraseInputScreen)
function buildRecoveryTarget(path, returnTo) {
  return returnTo ? `${path}?returnTo=${encodeURIComponent(returnTo)}` : path;
}

// After — no URL plumbing
navigate(path, { state: { nextPath: returnTo } });

Step 4 — Migrate per-screen types

Each local interface becomes:

type ProviderLaunchState = Partial<NavState>;
// or, if screen-specific extension needed:
type DiscloseResultState = Partial<NavState> & { resultSent?: boolean };

Step 5 — Document

Add to packages/webview-app/AGENTS.md:

Navigation state. Every navigate(path, { state }) uses a value typed as NavState (see src/types/navState.ts). Forward target = state.nextPath. Back target = state.backPath. Do not invent new slot names; extend NavState if you need a new well-typed field.

Validation

  • cd packages/webview-app && yarn types — clean.
  • grep -rn "returnTo" packages/webview-app/src — zero hits (decision q1 + q2 drop both the slot and the URL param).
  • grep -rn "searchParams.get..returnTo" packages/webview-app/src — zero hits (URL param removed).
  • grep -rn "as { [a-zA-Z]*Path" packages/webview-app/src — zero hits (all reads go through NavState).
  • Manual: recovery flow (settings → backup → secret phrase input → success) returns the user to the originating screen, regardless of state-only or URL+state path.
