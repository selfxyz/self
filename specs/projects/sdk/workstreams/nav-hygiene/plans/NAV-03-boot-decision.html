Why

AUDIT identifies "two boot deciders" — ModeBoot and InitialRouteRedirect. Investigation reveals only ModeBoot exists; InitialRouteRedirect does not. The actual problem is different: ModeBoot has two separate useEffect hooks — one for the fail-closed guard, one for route sync — that read overlapping state and fire on the same boot. The decision tree is split across them. NAV-03 collapses both into a single documented decision function with an explicit decision tree, fail-closed semantics, and unit tests.

New screen — /embed/error (generic embed-mode failure)

A persistent fallback rendered when the embed-mode boot guard fires (invalid verificationRequest, bridge errors, etc.). Shown for the brief window before lifecycle.dismiss() takes effect, and as a stable surface if dismiss() never succeeds.

Screen spec
  • Path: /embed/error. Mode metadata: embed (per NAV-13).
  • Trigger: BootDecision dispatches navigate('/embed/error', { replace: true, state: { code, message } }), then asynchronously calls lifecycle.setResult({ success: false, errorCode: code, errorMessage }).catch(() => {}) followed by lifecycle.dismiss({ reason: 'invalid_request' }).
  • Layout: centered title + body + (optional) "Close" button that calls lifecycle.dismiss again. Reuse Euclid's existing ErrorScreen if it accepts a generic title/body; otherwise add a local thin wrapper and file an Euclid follow-up.
  • Copy (draft, needs UX review): 
    Title: Verification couldn't start
Body:  The verification request was invalid or
       could not be completed. Please return to
       the app that opened this view.
CTA:   Close
  • Analytics: emit embed_error_shown with { code, message } on mount.
  • Telemetry: add a Mixpanel event so we can detect how often this surface is reached in production.
Coordination checklist
  • UX: confirm the copy and approve a layout (or point at an existing Euclid screen we can reuse).
  • Euclid: if a generic ErrorScreen isn't already exported, file an issue to add one. Track the version bump.
  • Bridge contract: confirm the host expects setResult({success:false, errorCode:'INVALID_REQUEST'}) on this path; document errorCode enum if more codes are needed.
  • Mobile app: the wallet shell ignores /embed/* routes today; verify mounting one doesn't trigger an unintended state change.

Why this is a problem

  • Decision tree split. Reading the file you can't see the full boot decision in one place.
  • No tests. tests/screens/tunnel/tunnelFlowScreens.test.tsx mocks OperatingModeProvider but doesn't cover ModeBoot's decision logic.
  • Implicit ordering. Effect 1 must fire before Effect 2 sees an invalid tunnel request. Currently relies on React effect ordering; fragile under future provider changes.

Approach

Step 1 — Extract the pure decision function

Create decideBootRoute in a new bootDecision.ts alongside the (renamed) BootDecision.tsx:

export type BootInputs = {
  isReady: boolean;
  mode: OperatingMode;
  verificationRequest: VerificationRequestContext | null;
  pathname: string;
};

export type BootAction =
  | { type: 'wait' }
  | { type: 'fail-closed', error: 'INVALID_REQUEST' }
  | { type: 'navigate', to: string, replace: true }
  | { type: 'noop' };

export function decideBootRoute(input: BootInputs): BootAction { ... }

Step 2 — Rewrite BootDecision as a single effect

The effect dispatches on the action. Fail-closed navigates to /embed/error first, then asynchronously calls the bridge so the user always has a stable surface while dismiss() resolves:

useEffect(() => {
  const action = decideBootRoute({ isReady, mode, verificationRequest, pathname: location.pathname });
  switch (action.type) {
    case 'wait':
    case 'noop':
      return;
    case 'navigate':
      navigate(action.to, { replace: action.replace });
      return;
    case 'fail-closed':
      if (failClosedFiredRef.current) return;
      failClosedFiredRef.current = true;
      navigate('/embed/error', { replace: true, state: { code: action.error } });
      lifecycle.setResult({ success: false, errorCode: action.error, errorMessage: 'Verification could not start.' }).catch(() => {});
      lifecycle.dismiss({ reason: 'invalid_request' });
      return;
  }
}, [isReady, mode, verificationRequest, location.pathname]);

Step 3 — Register /embed/error

Add the new route in App.tsx. If the Euclid screen from Action Items hasn't shipped, ship a local wrapper that reads location.state.code and renders the draft copy. Either way: this route must exist before NAV-03 ships, otherwise the fail-closed navigate dead-ends on the catch-all.

Step 4 — Unit tests

Six test cases mirroring the branches in Scope. No React tree needed — the function is pure. Snapshot the new fail-closed branch: action shape must include the error code so the component can pass it through to the bridge call.

Step 5 — Spec correction

Update SPEC.html backlog row NAV-03 title from "Collapse ModeBoot + InitialRouteRedirect into one boot decision function" to "BootDecision — single documented boot decision function with fail-closed UX" and rewrite the notes accordingly.
