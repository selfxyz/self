Why

Per SPEC invariant #7, every route is either a verb (an operation: /tour, /capture/*, /register/*, /disclose/*) or a place (a destination: /, /settings, /docs, /history). No journey prefixes (/onboarding), no mode prefixes (/tunnel). Journey context lives in code + Mixpanel funnels; mode lives in metadata (NAV-13's ModeRoute). NAV-08 is the namespace rewrite. Largest blast radius in the workstream — every route registration, every navigate() call, every state path, host deeplinks, tests, docs.

Pair with NAV-13. Routes get tagged with mode metadata at the same moment their paths change — one PR.

Decisions

Locked in on 2026-05-25. See DECISIONS.md.

  • nav-08-q1-tunnel-paths · Decided

    Rename /tunnel/* → /embed/*, or drop the mode prefix entirely?

    Drop the prefix entirely. Paths describe operations only; mode is enforced by NAV-13's <ModeRoute> wrapper, never by URL prefix. Strict invariant #7 compliance.

  • nav-08-q2-backcompat · Decided — chose hard cut over recommended redirect map

    Backwards-compat: redirect map for one release, or hard cut?

    Hard cut. No transitional redirects. Document the breaking change in the release notes. Coordinate with anyone shipping deeplinked SelfApp configs before the release ships.

    Pre-PR checklist: search public docs/, partner integration repos, and any rn-sdk fixtures for hard-coded old paths. Open coordination threads before the rewrite PR opens.

Scope

  • Rename every route registration in App.tsx per the mapping.
  • Update every navigate() call that uses an old path string. ~150+ call sites.
  • Update every state.nextPath / state.backPath string literal in screen code.
  • Update DevRouteMenu.tsx entries.
  • Update tests (tests/screens/tunnel/*, etc.).
  • Update host-integration deeplink docs (if any).
  • Document the breaking-change cutover per decision q2 (no transitional redirects).
  • Update SPEC.html and AUDIT.html prose to use the new paths.

Out of Scope

  • No Euclid changes. Screen content is unaffected.

  • No DEV gating changes — NAV-02 owns /dev/*.
  • No state-slot renames — NAV-09 owns that.
  • NAV-13's ModeRoute wrapper ships in the same PR but as logically separate work; the wrapper is documented in NAV-13's plan.

Approach

Step 1 — Mapping table is canonical

Treat the Path Mapping table above as the source of truth. Every old path appears exactly once.

Step 2 — Mechanical sed sweep

For each old → new pair, run a project-wide search-and-replace. Order matters: do longest paths first to avoid partial-prefix collisions. Run yarn types && yarn build && yarn test after each batch.

Step 3 — Apply the drop-prefix mapping

Per decision q1: /tunnel/* paths fold into self-app routes; mode-awareness is enforced by NAV-13's <ModeRoute> wrapper, which lands in the same PR. The mode prefix is gone from URLs forever.

Step 4 — Hard-cut cutover

Per decision q2: no transitional <Navigate> redirects. Document the breaking change in the release notes. Pre-PR coordination tasks:

  • Grep partner integration repos (any SelfApp host config) for hard-coded /tunnel/* or /proving/* path strings.
  • Open an issue / Slack thread with host integrators 1 week before the PR opens — share the new path map.
  • Update public docs/ with the new path names after the rewrite PR merges (not before, to avoid confusing the live state).

Step 5 — Cluster-collapse

Per SPEC notes (b)(c)(d)(e)(f)(g): the kyc-pending/success collapse, the register-success consolidation, the tunnel-kyc retirement, the recovery-phrase top-level move, and the notify top-level move all happen here. Track each in the PR description as a sub-bullet.

Step 6 — Test fixture sweep

Tests that mount routes or assert on pathnames need updating. Run yarn test at the package level.

Step 7 — Update SPEC + AUDIT prose

The path strings in SPEC.html (e.g. invariant prose, dependency graph labels) and AUDIT.html (route graph mermaid, finding articles) need to reflect the new namespace. Do this at the end so the spec doesn't drift mid-PR.
