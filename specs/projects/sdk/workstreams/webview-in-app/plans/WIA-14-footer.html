Context

You are showing the host-minted correlationId as a copyable reference on WebView error screens, completing the ANA-15 re-home. A user reporting a failure copies the reference; an engineer searches Sentry correlation_id:<value> and pulls every event for that session across both runtimes. PR1 minted correlationId, propagated it via URL + lifecycle.getConfig, and exposed it through useOperatingMode() on OperatingModeContextValue.correlationId. This PR consumes that — it adds no new source.

ANA-15 behavior: a small muted Reference: <id> line, shown only when an id is available, tap-to-copy, ~1s confirmation. RN used dinot/slate400; the web component uses Euclid colors tokens.

Decisions

  1. Source is the reactive context value, read through a hook. Add useCorrelationId() returning useOperatingMode().correlationId. The component reads it during render and re-renders when the context updates (the id can resolve after first paint, once getConfig returns). Do not snapshot it into local state at mount — that would freeze a null. React context already provides the subscription; no useSyncExternalStore is needed because the value lives in OperatingModeProvider state.
  2. Net-new webview-app component, not Euclid. packages/webview-app/src/components/CorrelationReference.tsx — runtime-specific (web DOM, clipboard), like the web PrivacyMask (WIA-13). Use Euclid colors for the muted text; no raw hex.
  3. Compose around the Euclid result screens, never fork them. The failure surfaces render Euclid components (KycFailureScreen, ProofFailureScreen, StatusState) with no footer slot. Render <CorrelationReference /> as a sibling pinned to the bottom of each screen container. If a layout can't host a sibling without overlap, note it in the PR rather than restyling the Euclid screen.
  4. Copy with graceful fallback; local confirmation. navigator.clipboard.writeText when available, else hidden-textarea execCommand('copy') (some WebView/CSP contexts block the async API). Confirmation is a ~1s in-component state, not a global toast.
  5. Render nothing when no id. useCorrelationId() null → component returns null (no empty “Reference:”). This is also the old-host / browser-mode path from PR1's Compatibility section.

Implementation

  1. Hook. export const useCorrelationId = () => useOperatingMode().correlationId.
  2. Component. Read useCorrelationId(); if falsy return null; else render a centered muted pressable Reference: {id} that copies and flips to a ~1s “Copied” state. Euclid colors for text. Keep <~70 LOC.
  3. Mount. In each inventory screen, render <CorrelationReference /> as the last child of the screen container, on the failure branch for the result/verification screens.
  4. DRY check. No existing reference/support-id footer exists in webview-app (RN's SupportUuidRow has no web port). If one appears, extend it.

Tests

  • Renders null with no id; renders Reference: <id> when present.
  • Reactive: mount with context correlationId = undefined, then update the provider value → the footer appears without remount. This guards Decision 1.
  • Copy: click copies (mock navigator.clipboard.writeText) and shows the confirm state; fallback path exercised when the async API is absent.
  • Integration: render one failure route inside OperatingModeProvider with a seeded correlationId and assert the footer shows it; render a success route and assert no footer. Use the provider's seam to inject the id deterministically (see Validation).
