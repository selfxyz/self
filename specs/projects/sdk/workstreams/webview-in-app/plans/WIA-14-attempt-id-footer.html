Context

You are porting ANA-15's attempt_id reference footer onto the webview-app error screens, so an engineer reading a failed verification can copy the attempt's reference and pull every correlated event (RN host + WebView) from the shared Sentry project. Cross-runtime correlation is by attempt_id (SPEC-OBSERVABILITY Decision 6); today only Sentry carries it — nothing is shown to a user who needs to report a failure.

Per SPEC-OBSERVABILITY Decision 8, ANA-15 does not ship against React Native: it is re-homed here. You do not build app/src/components/AttemptReference.tsx. The footer is a net-new webview-app component using Euclid tokens.

Prerequisite + central design finding (verified in code). The SPEC says “add the missing getCurrentAttemptId() accessor first.” That accessor does not exist. More importantly, the onboarding-funnel singleton that holds the attempt id (currentAttempt in packages/mobile-sdk-alpha/src/analytics/onboardingFunnel.ts:38) is driven exclusively by the RN app — every trackBranchEvent / trackOnboardingStep call site is under app/src/; webview-app calls none of them. In the WebView runtime the singleton is null, so a naive getCurrentAttemptId() returns nothing web-side until cutover (WIA-11) moves the funnel into the WebView. The id the WebView does have today arrives as the attempt_id property on analytics events, already extracted by packages/webview-app/src/observability/observedAnalytics.ts via tagsFromAnalyticsEvent. The footer must source from there. See Decision 2.

What ANA-15 specifies the footer renders (ANA-15 plan): a small muted Reference: <attempt_id> line, shown only when an attempt id is available, tap-to-copy, with a ~1s confirmation toast. RN used dinot / slate400; the web component uses Euclid tokens instead.

Decisions

  1. Add getCurrentAttemptId() to the funnel and export it from both entrypoints. In onboardingFunnel.ts add export function getCurrentAttemptId(): string | null { return currentAttempt?.id ?? null; } (it can wrap the existing _getCurrentOnboardingAttempt()). Export from src/index.ts (RN) and src/browser.ts (WebView). This is the durable post-cutover source of truth and is cheap; it is necessary but not sufficient web-side today (see Decision 2).
  2. The footer reads attempt id from a WebView-local accessor that prefers the funnel and falls back to the last id seen on the analytics stream. Add a tiny module packages/webview-app/src/observability/attemptId.ts exporting setLastSeenAttemptId(id) and getDisplayAttemptId(). In observedAnalytics.ts, where tagsFromAnalyticsEvent already runs, capture properties.attempt_id via setLastSeenAttemptId when present. getDisplayAttemptId() returns getCurrentAttemptId() ?? lastSeen ?? null. This is correct pre-cutover (RN drives the funnel, the WebView mirrors the id from events it relays) and post-cutover (the WebView drives the funnel and the first branch wins). Do not add a new bridge call — the id is already in the event payloads the WebView relays.
  3. The footer is a net-new webview-app component, not Euclid. Like the web PrivacyMask (WIA-13 Decision 4), it is runtime-specific (web DOM, copy-to-clipboard, app analytics correlation) and lives in packages/webview-app/src/components/AttemptReference.tsx — not @selfxyz/euclid. Use Euclid colors for the muted text (match existing webview-app screens, e.g. VerificationResultScreen.tsx imports { colors } from '@selfxyz/euclid'). No raw hex.
  4. Mount the footer by composing it around the Euclid result screens, not inside them. The failure surfaces render Euclid screen components (KycFailureScreen, ProofFailureScreen, StatusState) which do not expose a footer slot. Render <AttemptReference /> as a sibling positioned at the bottom of the screen container in each webview-app wrapper; do not fork the Euclid component. If a wrapper's layout cannot host a sibling footer without overlap, note it in the PR rather than restyling the Euclid screen.
  5. Copy uses the web Clipboard API with a graceful fallback; the toast is local. navigator.clipboard.writeText when available, else a hidden-textarea document.execCommand('copy') fallback (some WebView/CSP contexts block the async API). The confirmation is a short in-component visual state (~1s), not a global toast system — keep it self-contained so the component drops onto any screen.
  6. Render nothing when there is no id. When getDisplayAttemptId() is null the component returns null (no empty “Reference:” label), matching ANA-15's “only when an active attempt exists.”

Implementation

  1. SDK accessor. Add getCurrentAttemptId() to onboardingFunnel.ts; wire both exports. Run yarn build in mobile-sdk-alpha so the ./browser dist picks it up before webview-app imports it.
  2. WebView accessor module. Create attemptId.ts holding a module-scoped lastSeen: string | null. getDisplayAttemptId() imports getCurrentAttemptId from @selfxyz/mobile-sdk-alpha/browser and returns getCurrentAttemptId() ?? lastSeen.
  3. Feed it from the analytics observer. In observedAnalytics.ts, immediately after the existing tagsFromAnalyticsEvent call, add if (typeof properties?.attempt_id === 'string') setLastSeenAttemptId(properties.attempt_id);. No other behavior changes.
  4. Component. Build AttemptReference.tsx: call getDisplayAttemptId(); return null if falsy; otherwise render a centered muted line Reference: {id} as a button/pressable that copies and shows a 1s “Copied” state. Use Euclid colors for text. Keep it <~60 LOC.
  5. Mount sites. In each of the four screens, render <AttemptReference /> as the last child of the screen container; gate the two result screens to the failure branch only (they already branch success/failure on the Euclid component they pick — mount the footer in the same failure path).
DRY check before writing. Confirm webview-app has no existing reference/support-id footer (RN's SupportUuidRow has no web port as of this plan). If one appears during implementation, extend it instead of adding a second component.

Spec corrections

Update SPEC-OBSERVABILITY (the In-scope bullet at line ~114 and Decision 8 at line ~194) and the WIA-14 backlog rows to reflect verified code:

  • Target screens are wrong by name. The SPEC lists the RN screens (KycFailureScreen, DocumentNFCTroubleScreen, ProofRequestStatusScreen failure, AadhaarUploadErrorScreen). The actual webview-app failure surfaces are EmbedKycFailureScreen, EmbedResultScreen (failure), DiscloseResultScreen (failure), and VerificationResultScreen (failure).
  • No web equivalents exist for the NFC-trouble or Aadhaar-upload error screens. NFC and Aadhaar capture are native bridge flows with no WebView DOM screen, so there is nothing to port there. Drop them from the WIA-14 scope list.
  • The accessor alone is insufficient pre-cutover. SPEC Decision 8 implies getCurrentAttemptId() is the footer's source. The funnel singleton is RN-host-driven and empty in the WebView until WIA-11. Record that WIA-14 sources the id from the analytics-event stream with the accessor as the preferred/post-cutover path (Decision 2 here).

Tests

  • SDK (mobile-sdk-alpha). Unit test getCurrentAttemptId(): null before any attempt; the attempt id after a tracked start; null after a terminal event. Reuse _resetOnboardingFunnelForTests().
  • WebView accessor. Test getDisplayAttemptId() precedence: funnel value wins; falls back to lastSeen when funnel is null; returns null when neither is set.
  • Component. Render test: returns null with no id; renders Reference: <id> when present; clicking copies (mock navigator.clipboard) and shows the confirm state. Assert real behavior, not just that clipboard was called.

Out of scope

  • Building or modifying any RN component — ANA-15 does not ship against RN (Decision 8). You will NOT create app/src/components/AttemptReference.tsx or touch RN error screens.
  • New bridge calls or protocol changes to fetch the attempt id. It already rides on analytics event properties.
  • Changing the cohort-tag taxonomy, the redact regex, or tagsFromAnalyticsEvent behavior (owned by the analytics/ workstream).
  • A global toast/notification system. The confirmation is component-local.
  • Porting SupportUuidRow or other RN support-footer UI wholesale.
