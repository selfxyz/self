Context

You are adding Session Replay to the WebView app and masking the PII it renders. WIA-12 already shipped @sentry/react (^9.32.0), packages/webview-app/src/config/sentry.ts with initSentry(), the runtime: webview tag, cohort-tag setters, and the shared redactSensitiveFields beforeSend hook. That config deliberately does not register the replay integration — its inline comment hands replay sample rates and DOM mask wrappers to this plan.

The RN host runs mobileReplayIntegration({ maskAllText, maskAllImages, maskAllVectors }) at 10% session / 100%-on-error (app/src/config/sentry.ts). You are bringing the WebView to parity so cutover (WIA-11) does not regress replay coverage, and so a replay opened from a WebView error groups with RN-host events by attempt_id in the shared Sentry project.

Scope-narrowing finding (verified in code). The SPEC-OBSERVABILITY mask-site list (“biometric capture / NFC scan / data confirmation / Aadhaar / KYC verified”) is written against RN screen names and is stale for the web side. In webview-app, camera (MRZ) and NFC are delegated to native bridge handlers (bridge.request('camera', …), bridge.request('nfc', …)): no camera frames or chip data render in the WebView DOM, so replay cannot capture them. MRZ fields do transit WebView route state and the NFC bridge call, but are not displayed on the NFC/progress screens — so replay risk there is low. The confirmation, Aadhaar-instructions, and KYC-success screens render only static instruction/success text.

The web-side DOM surfaces that render or accept real PII — the mask sites:

  • packages/webview-app/src/screens/home/IDDataScreen.tsx — name, DOB, sex, nationality, document number, place of birth, issue/expiry dates, photo, and full MRZ lines (currently mock data; real document data in production).
  • packages/webview-app/src/screens/recovery/RecoveryPhraseScreen.tsx — renders the 24-word mnemonic after reveal.
  • packages/webview-app/src/screens/recovery/SecretPhraseInputScreen.tsx — accepts the mnemonic in DOM inputs.

Global maskAllText / maskAllInputs cover all three. Wrap IDDataScreen and RecoveryPhraseScreen in the explicit PrivacyMask (rendered text); the mnemonic inputs on SecretPhraseInputScreen are covered by maskAllInputs — wrap it too if the inputs sit inside a single container, otherwise rely on the global default and note it.

Decisions

  1. Always-on global masking is the primary defense. Register replayIntegration({ maskAllText: true, maskAllInputs: true, blockAllMedia: true }) in the existing initSentry(). With these defaults every text node, input, and media element (img/svg/video/canvas) is redacted before it leaves the browser. The WebView never disables these, per the SPEC invariant.
  2. Mobile replay options translate to browser options. The browser replayIntegration has no maskAllImages/maskAllVectors — the RN-baseline intent maps as below. Implement the browser column; do not try to set the mobile names.
    RN mobileReplayIntegrationBrowser replayIntegration
    maskAllText: truemaskAllText: true
    (inputs implicit)maskAllInputs: true
    maskAllImages: trueblockAllMedia: true (covers <img>)
    maskAllVectors: trueblockAllMedia: true (covers <svg>)
  3. Sample rates match the RN non-simulator baseline. replaysSessionSampleRate: 0.1, replaysOnErrorSampleRate: 1.0. There is no simulator notion in the WebView, so no conditional gating — replay runs whenever Sentry is enabled (isSentryEnabled, i.e. a DSN is configured). Match WIA-12's gating exactly; add no new enable flag.
  4. Add a web PrivacyMask as explicit, durable defense-in-depth. Mirror app/src/observability/PrivacyMask.tsx with a thin webview-app component that wraps children in an element carrying Sentry's default sentry-mask class. Wrap the IDDataScreen render with it. This is belt-and-suspenders: global masking already covers the screen, but the explicit wrapper documents intent and survives any future change to the global defaults. The component is runtime-specific (web DOM + Sentry CSS convention), so it lives in webview-app — not Euclid — exactly as RN keeps its own.
  5. No cross-bridge exception forwarding (unchanged from WIA-12). A WebView JS error is captured by @sentry/react directly; the replay is attached client-side. Nothing is serialized over the bridge to the RN host.
Bundle cost (non-blocking). Importing replayIntegration pulls the replay recorder into the embedded WebView bundle (the project loads embedded-only — no OTA). This is the expected cost of replay parity; do not add a remote/lazy path to avoid it. If the build-size check flags it, note the delta in the PR description rather than dropping replay.

Implementation

1 · Register the replay integration

In packages/webview-app/src/config/sentry.ts, import replayIntegration from @sentry/react and add it to the existing integrations factory return, then set the two sample rates in sentryInit:

import { breadcrumbsIntegration, init as sentryInit, replayIntegration, setTag } from '@sentry/react';

// inside sentryInit({ ... }):
integrations: defaults => [
  ...defaults.filter(integration => integration.name !== 'Breadcrumbs'),
  breadcrumbsIntegration({ console: false, dom: false }),
  replayIntegration({ maskAllText: true, maskAllInputs: true, blockAllMedia: true }),
],
replaysSessionSampleRate: 0.1,
replaysOnErrorSampleRate: 1.0,

Leave runtime: webview, tracesSampleRate: 0, and the beforeSend redaction exactly as WIA-12 left them.

2 · Add the web PrivacyMask component

Create packages/webview-app/src/observability/PrivacyMask.tsx mirroring the RN component's shape (props passthrough, no logic). It renders a wrapper element carrying Sentry's default sentry-mask class so all descendant text is redacted in replay regardless of the global default. Accept an optional className and merge it.

3 · Wrap the PII screens

Wrap each web-side PII surface in <PrivacyMask> without modifying the underlying Euclid components or data props:

  • IDDataScreen.tsx — wrap the returned <EuclidIDDataScreen … />. The card photo is an <img> covered by blockAllMedia; text fields and MRZ lines by both maskAllText and the wrapper.
  • RecoveryPhraseScreen.tsx — wrap the revealed mnemonic.
  • SecretPhraseInputScreen.tsx — wrap the input container if single; else rely on maskAllInputs and note it.

4 · Verify no CSP blocks the replay worker

Sentry Session Replay runs its recorder in a WebWorker. If the WebView or served bundle sets a Content-Security-Policy, replay startup needs worker-src 'self' blob: (or child-src as fallback). No CSP was found in webview-app at planning time — confirm none is injected by the RN WebView host or the embedded-bundle server, and if one exists, add the worker directive. Source: Sentry Session Replay docs (docs.sentry.io/platforms/javascript/session-replay/).

Required constraints. Do not import @sentry/react from anywhere outside webview-app/src/config/sentry.ts. The new PrivacyMask applies only a CSS class and must not import Sentry. Do not add replay config to mobile-sdk-alpha or webview-bridge. Do not lower maskAllText/maskAllInputs/blockAllMedia, add an unmask/.sentry-unmask selector, or enable replay only behind a non-DSN flag.
