Purpose

PR #2108 landed the build-side prototype of Path A (rn-sdk wrapping kmp-sdk for the secureStorage domain on Android). Smoke is PASS. This plan covers the rollout from prototype to full migration: extend the wrap pattern to the remaining bridge domains, add the iOS Swift-provider scaffolding (KMP iOS still has cinterop disabled — all iOS handlers delegate to consumer-supplied Swift providers via IosProviderRegistry), retire the duplicated TS handlers one domain at a time, and converge the bridge envelope drift only after enough domains are on Path A to make convergence cheap.

This plan does not touch app/ (Self app) integration. That happens at WIA-11 cutover, after all domains are migrated and SD-06 has shipped hosted Maven publishing. The same applies to converging the selfxyz/self ↔ selfxyz/self-webview-sdk kmp-sdk forks — that decision is captured below as a prerequisite, not as a sub-task of this plan.

Prerequisites

The two-repo split is narrower than the earlier framing suggested. This repo's packages/kmp-sdk/ was deliberately scoped to 3 domains (secureStorage, crypto, lifecycle) by Seshanth's commit 37b8f0ca7 (#1915, 2026-04-04). The private selfxyz/self-webview-sdk repo (created 2026-04-10) is where the optional MOD modules (nfc, camera, biometrics) live. Domains #1–#4 of this rollout work against this repo's kmp-sdk as-is and do not need either prerequisite resolved. P-1 / P-2 only matter for #5–#7.

P-1 · Source of MOD handlers for #5–#7

nfc, biometrics, and camera handlers are not in this repo's kmp-sdk — they were intentionally stripped on 2026-04-04 (#1915) and re-live in the private fork's MOD-01/02/04 work. Before the rollout reaches those domains, decide how their handlers reach rn-sdk:

  • A — Publish the private fork as a Maven artifact (likely via SD-06) and have rn-sdk/android/build.gradle consume it under a different artifact coordinate than the public one. Cleanest; doesn't pull private code into this public repo.
  • B — Merge MOD work back into this repo's packages/kmp-sdk/. Simplest from rn-sdk's perspective; pushes the optional modules into the public tree.
  • C — Mirror script. Keeps both alive; doubles maintenance. Not recommended.

Decision owner: Seshanth + Rémi. Deadline: before WIA-17 domain #5 (biometrics). Domains #1–#4 ship regardless.

P-2 · SD-06 hosted Maven publishing (SELF-2534)

Currently rn-sdk-test-app resolves xyz.self.sdk:shared-android:0.1.0 via mavenLocal(). That works for prototype dev but forces every consumer (including Self app) to run ./gradlew publishToMavenLocal before building. SD-06 publishes KMP artifacts to GitHub Packages so consumers just declare a Maven repo + creds. mavenLocal() is sufficient for domains #1–#4. SD-06 is the natural delivery vehicle for P-1 option A (publish the private fork as an artifact), and is required regardless before Self app integration (WIA-11 cutover).

Decision owner: Ayman (assigned). Deadline: before WIA-11; ideally before #5.

iOS Swift-provider scaffolding (domain #2 lands this)

KMP iOS handlers are NotImplementedError stubs that delegate to IosProviderRegistry (cinterop is disabled in packages/kmp-sdk/shared/build.gradle.kts). Re-enabling cinterop is a separate, larger decision owned by Seshanth. For this rollout, the iOS path is: RN consumer registers Swift providers into IosProviderRegistry before mounting the WebView. The scaffolding domain #2 needs to land:

  • packages/rn-sdk/ios/SelfBridgeModule.swift — RCT module that exposes routeMessage(_:) to JS and forwards to a long-lived MessageRouter instance from the KMP XCFramework. Constructs and registers SecureStorageBridgeHandler on init.
  • packages/rn-sdk/ios/SelfBridgeModule.m — RCT bridge glue (RCT_EXTERN_MODULE + method exports), mirroring the pattern in SelfMRZScannerModule.m.
  • Swift SecureStorageProvider implementation that wraps Keychain Services with the same key namespacing as the Android provider (self_sdk_secure_prefs equivalent — single shared keychain access group).
  • selfxyz-rn-sdk.podspec updates: add SelfSdk.xcframework as a vendored framework, ensure the consumer Podfile picks it up through autolinking.

Open question, surface to Seshanth: the KMP SelfSdk.xcframework is built from ./gradlew createXCFramework in packages/kmp-sdk/. That task currently produces debug variants only (see packages/kmp-sdk/shared/build.gradle.kts:184). SD-06's DoD includes switching to release; the iOS PR needs release variants to ship in a podspec. Either domain #2 fixes that task to produce release variants too, or it depends on SD-06 progress.

Retiring TS handlers

Each domain PR retires the corresponding TS handler in a follow-up commit on the same PR, after smoke passes. The follow-up commit:

  1. Updates SelfVerification.tsx to remove the domain from the useKmpBridge-gated branch — once the KMP path is the only path, the flag isn't needed for that domain.
  2. Deletes the {Domain}Handler.ts file + its test.
  3. Removes the handler from createHandlers in packages/rn-sdk/src/handlers/index.ts.
  4. If the domain had an associated RN-native module (e.g. SelfCryptoModule.kt), deletes it and any Swift counterpart.

Do not bulk-delete TS handlers in a sweep PR. The per-domain pairing keeps every revert window small. After domain #8 lands, the useKmpBridge flag becomes vestigial and is deleted in a final cleanup PR.

Bridge envelope drift — parking lot

KMP's MessageRouter and TS's MessageRouter emit response envelopes with minor differences observed during the spike:

  • Missing-handler error code: KMP emits DOMAIN_NOT_FOUND; TS emits HANDLER_NOT_FOUND.
  • Malformed-message handling: KMP drops silently; TS logs to console.error first.
  • isTrustedSource parameter: KMP requires a boolean second arg on onMessageReceived; TS has no equivalent. The RN bridge module currently hardcodes true.

Do not converge these until at least 3 domains are on Path A. Converging the envelope now would require touching code in both kmp-sdk and rn-sdk, doubling the surface of the next 2–3 PRs without buying anything functional. Once domains #1–#3 are merged, file a follow-up that picks the canonical shape (KMP's, since that's where the WebView protocol contract is authoritative per the umbrella spec invariants) and patches the TS side once.

Out of scope

  • app/ (Self app) integration. Comes at WIA-11 cutover, after all domains migrated + SD-06 shipped.
  • Re-enabling KMP iOS cinterop. Larger decision owned by Seshanth. This rollout works with cinterop disabled by going through the Swift provider model.
  • Converging the two-repo split. Captured as prerequisite P-1, not a sub-task of this plan.
  • Bridge protocol version bumps. The drift in the parking lot is envelope-level; the protocol version stays at 1 throughout this rollout.
  • New bridge domains. The 10 existing domains are fixed by the umbrella spec; this plan only migrates the existing ones.
  • Performance optimization. The native-RN-native-RN round-trip is acceptable per the smoke; defer profiling until cutover prep.
