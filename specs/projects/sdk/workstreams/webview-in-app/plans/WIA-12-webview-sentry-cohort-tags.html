Context

You are adding the WebView-side Sentry surface. WIA-09 added RN-host load diagnostics in app/src/config/sentry.ts, including runtime: rn-host, webview_source, and the live PII key redaction pattern. webview-app still has no Sentry dependency or cohort-tag wiring, so WebView errors cannot be searched by the same attempt_id / document cohort tags as RN-host events.

You are extracting shared pure observability helpers into mobile-sdk-alpha. You are not implementing Session Replay masking (WIA-13) or the attempt footer (WIA-14).

Decisions

  1. Use @sentry/react, not @sentry/browser, in packages/webview-app. This matches the React + Vite app shape and allows React error-boundary/profiler integration.
  2. Extract the live RN redaction pattern from app/src/config/sentry.ts; do not define a new shorter regex. The current pattern is:
/passport|mrz|dg\d|chip|aadhaar|(?:first|last|full|given|family|holder|sur)_?name|name_?(?:first|last|of_?holder|holder)|date_?of_?birth|dob|birth|photo/i
  1. Split app/src/observability/onboardingContext.ts instead of moving it wholesale. packages/mobile-sdk-alpha/src/ must remain platform-agnostic and cannot import @sentry/react-native.
  2. Runtime-specific Sentry setters stay runtime-specific. RN uses @sentry/react-native; WebView uses @sentry/react.

Implementation

1 · Extract pure shared helpers

Create a platform-agnostic observability module in mobile-sdk-alpha:

  • Move OnboardingTagSnapshot, the cohort key list, and tagsFromAnalyticsEvent() out of app/src/observability/onboardingContext.ts.
  • Move sanitizeTagValue from app/src/config/sentry.ts if it is pure and does not depend on RN/Sentry. If it has runtime coupling, create a pure SDK equivalent and update RN to use it.
  • Move the live SENSITIVE_KEY_PATTERN from app/src/config/sentry.ts exactly as-is.
  • Export a redaction helper that can redact breadcrumb/event data, contexts, and extra without importing a Sentry SDK.

Required constraint: no imports from react-native, @sentry/react-native, @sentry/react, browser globals, or app aliases in the SDK module.

2 · Preserve RN behavior

Update app/src/config/sentry.ts to use the shared redaction pattern/helper. Keep captureWebViewLoadDiagnostic() behavior unchanged:

  • runtime: rn-host
  • webview_source: bundle | dev-server
  • error_code: timeout | load_error | version_mismatch
  • existing warning/error level semantics

Update app/src/observability/onboardingContext.ts so it still exports the names current RN importers use, but the concrete Sentry.setTag() calls remain in app/.

3 · Add WebView Sentry config

Install @sentry/react in packages/webview-app.

Create a WebView Sentry config that:

  • Initializes only when a DSN is configured for the WebView app.
  • Sets runtime: webview at init and never clears it.
  • Applies the shared redaction helper in beforeSend.
  • Exposes setOnboardingTags(snapshot) and clearOnboardingTags() wrappers around @sentry/react tag APIs.
  • Does not forward WebView exceptions over the RN bridge.

Do not add Session Replay in this PR; WIA-13 owns replay sample rates and mask wrappers.

4 · Wire cohort tags from WebView analytics

Hook the existing WebView analytics path. packages/mobile-sdk-alpha/src/adapters/browser/analytics.ts already has trackEvent(event, payload), so the WebView side has a clean interception point. The SDK adapter may expose a pure callback hook, but the Sentry call itself must be wired from webview-app.

For every tracked onboarding event:

  • Build a snapshot via shared tagsFromAnalyticsEvent(eventName, properties).
  • Call WebView setOnboardingTags(snapshot) for non-terminal onboarding events from a webview-app wrapper/callback.
  • Call WebView clearOnboardingTags() when the event is terminal from the same runtime-local wrapper/callback.
  • Keep Mixpanel/Segment delivery RN-host-only through the bridge; do not add Segment or Mixpanel to webview-app.

Terminal clear semantics must match RN. The current RN code clears on OnboardingEvents.ENDED (Onboarding: Ended), not on a hand-maintained list of outcome strings.

Required constraint: neither packages/mobile-sdk-alpha/src/adapters/browser/analytics.ts nor packages/webview-bridge/src/ imports @sentry/react or packages/webview-app/src/config/sentry. Those packages can accept callbacks/adapters; only webview-app owns concrete Sentry wiring.
